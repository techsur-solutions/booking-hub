Create BookingEdit page loading booking by ID from URL (/bookings/:id/edit).

On mount:
1. Fetch booking via `bookings.getById(id)` API
2. If booking.recurrence_pattern !== null: show RecurringScopeDialog modal immediately (blocking, cannot dismiss without selecting scope)
3. User selects scope: "This occurrence only" or "Entire series"
4. Store scope in state: `scope: 'this-only' | 'entire-series'`
5. Render BookingForm with mode='edit' and initialValues from booking

RecurringScopeDialog component:
- Modal (non-dismissible, no X button, no click-outside-to-close)
- Header: "Edit Recurring Booking"
- Body: "This is a recurring booking. How do you want to edit it?"
- Two buttons (large, full-width):
  - "This occurrence only" → onClick={() => onScopeSelect('this-only')}
  - "Entire series" → onClick={() => onScopeSelect('entire-series')}
- Footer: small text "This choice cannot be changed after saving."

Scope affects API call:
- this-only → PATCH /bookings/:id with query param ?scope=this-only
- entire-series → PATCH /bookings/:id with query param ?scope=entire-series

From TechArch-BookingHub.md §4.2.3:
```typescript
PATCH /bookings/:id?scope=this-only|entire-series
Request: { title?, location_id?, start_time?, end_time?, resource_ids?, custom_field_values? }
Response (200): { id: string; status: string; recurrence_updated_count?: number; ... }
```

Non-recurring bookings skip dialog entirely, proceed directly to form.

<task type="auto">
  <name>Task 2: Re-validation and post-save summary</name>
  <files>frontend/src/pages/BookingEdit.tsx</files>
  <action>
BookingForm in edit mode runs same validation as create mode:
- Real-time conflict detection via ConflictWarning component (same as create)
- Custom field validation (required fields, option validation)
- Start/end time validation (end > start)
- Hard-block vs soft-warn logic (same permission check as create)

Save flow:
1. Click Save button
2. If conflicts and user is non-approver → blocked
3. If conflicts and user is approver → confirmation dialog
4. PATCH /bookings/:id?scope={scope} with updated fields
5. On 200 response: show StateConfirmationBanner with scope-specific message:
   - If scope='this-only': "Only this occurrence changed at {timestamp}" (blue banner)
   - If scope='entire-series' AND response.recurrence_updated_count > 0: "Entire series updated ({recurrence_updated_count} occurrences) at {timestamp}" (blue banner)
   - If scope='entire-series' AND recurrence_updated_count === 1: "Only this occurrence changed (series already modified)" (blue banner)
6. Redirect to Calendar View with date=booking.start_time.split('T')[0]

Error handling:
- 400 validation error → inline field errors
- 409 conflict → error toast "Conflict detected"
- 404 booking not found → error toast "Booking not found", redirect to /calendar
- 500 server error → error toast "Failed to update booking"

Re-validation guarantee: Every edit triggers fresh conflict check (does not trust original booking.conflict_flags). This ensures concurrent edits don't create undetected conflicts.
