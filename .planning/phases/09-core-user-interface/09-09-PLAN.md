CustomFieldRenderer fetches custom field templates via `useCustomFields(locationId)` hook. For each template, renders field based on field_type:

Custom field values stored in form state as `{ [field_definition_id]: value }` object, submitted to backend as custom_field_values array per TechArch POST /bookings schema:

  description?: string;
  custom_field_values?: Array<{ field_definition_id: string; value: string }>;
  recurrence_pattern?: { type: 'daily' | 'weekly'; until: string };
}
Response (201): { id: string; status: 'pending' | 'approved'; ... }

<task type="auto">
  <name>Task 2: Real-time conflict detection with hard-block vs soft-warn</name>
  <files>frontend/src/components/booking/ConflictWarning.tsx</files>
  <action>
Create ConflictWarning component wrapping conflict detection logic per UI-BOOK-04.

On form change (location, start_time, end_time, resource_ids change), call `bookings.checkConflicts()` API (debounced 500ms) with current form values. API returns conflict_flags array (from Phase 5 backend):

```typescript
// From TechArch-BookingHub.md §4.2.6
GET /bookings/conflicts?location_id=X&start_time=Y&end_time=Z&resource_ids=A,B
Response: {
  conflicts: Array<{
    booking_id: string;
    booking_title: string;
    conflict_type: 'location' | 'resource';
    resource_id?: string; // for resource conflicts
  }>
}
```

ConflictWarning renders:
- **If conflicts.length === 0**: no warning, Save button enabled
- **If conflicts.length > 0 AND user lacks allowApproveBooking permission**: 
  - Red banner: "Conflict detected with {booking_title} ({conflict_type}). Resolve conflicts to proceed."
  - List all conflicting booking IDs as links to Detail Modal
  - **Save button DISABLED (hard-block)**
- **If conflicts.length > 0 AND user has allowApproveBooking permission**:
  - Yellow banner: "Warning: Conflict detected with {booking_title} ({conflict_type}). You can save anyway (approvers only)."
  - List all conflicting booking IDs
  - **Save button ENABLED with confirmation dialog on click: "Save despite conflict?"**

Permission check: `keycloak.realmAccess.roles.includes('role_booking_approver')` per Phase 3 implementation.
  </action>

<task type="auto">
  <name>Task 3: Recurring pattern selector and save with status confirmation</name>
  <files>frontend/src/components/booking/RecurringPattern.tsx</files>
  <action>
Create RecurringPattern component rendering when "Make this recurring" checkbox checked:

- **Repeat** dropdown: "Daily", "Weekly"
- **Until** date picker (required, must be >= start_time date)

Component exports `{ type: 'daily' | 'weekly', until: string }` object, included in form submission as recurrence_pattern.

Save flow:
1. Click Save button
2. If conflicts and user is non-approver → save blocked (from ConflictWarning)
3. If conflicts and user is approver → show confirmation dialog "Save despite conflict?"
4. POST /bookings with all form data
5. On 201 response: show StateConfirmationBanner with status from response:
   - If response.status === 'approved': "Booking approved at {timestamp}" (green banner)
   - If response.status === 'pending': "Booking submitted for approval at {timestamp}" (yellow banner)
6. Redirect to Calendar View with date=booking.start_time.split('T')[0]

Error handling:
- 400 validation error → show inline error messages under fields
- 409 conflict (should not happen if conflict detection working) → show error toast "Conflict detected. Please refresh and try again."
- 500 server error → show error toast "Failed to create booking. Please try again."
  </action>
