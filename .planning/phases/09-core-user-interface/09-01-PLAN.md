**Sidebar.tsx** — Replace Phase 2's flat link list with permission-gated navigation per UI-PATTERN-03 ("deny-by-default permission visibility"):

```tsx
const userRoles = keycloak.realmAccess?.roles || [];
const hasApprovePermission = userRoles.includes('role_booking_approver');
const hasAnyAdminPermission = userRoles.some(r => 
  r.includes('admin') || r === 'role_location_manager' || r === 'role_permission_manager'
);

return (
  <nav>
    <Link to="/bookings?view=month">Calendar</Link>
    {hasApprovePermission && <Link to="/approvals">Approvals</Link>}
    <Link to="/feeds">Feeds</Link>
    {hasAnyAdminPermission && (
      <section>
        <h3>Admin</h3>
        <Link to="/admin/locations">Locations</Link>
        <Link to="/admin/resources">Resources</Link>
        <Link to="/admin/custom-fields">Custom Fields</Link>
        <Link to="/admin/users">Users</Link>
        <Link to="/admin/roles">Roles & Permissions</Link>
        <Link to="/admin/settings">Settings</Link>
        <Link to="/admin/audit-log">Audit Log</Link>
      </section>
    )}
    <Link to="/account">My Account</Link>
  </nav>
);
```

Active route highlighting: use `useLocation()` to match current pathname and apply `active` class.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| {client→Gateway} | Frontend reads Keycloak JWT roles from in-memory token to render/hide nav; UI visibility is convenience only, authorization enforced server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | Sidebar permission gating | accept | UI permission checks read `keycloak.realmAccess.roles` from the JWT already validated by Keycloak; user can inspect/modify client state but cannot escalate server-side permissions. Gateway and service-layer authorization is the trust boundary. |
| T-09-02 | Information disclosure | Logout action | mitigate | `keycloak.logout()` in `UserMenu.tsx` clears local session and redirects to Keycloak logout endpoint per OIDC RP-initiated logout spec; no sensitive tokens persist in browser storage after logout. |
</threat_model>
