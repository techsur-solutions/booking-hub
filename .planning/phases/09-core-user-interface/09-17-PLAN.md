**Gap Reference:** UAT Test #6 reported "new bookings page does not have any locations so I am not able to create one" (blocker severity).

**Root cause:** API calls failing because JWT token expires before component mounts. Current interceptor (from 09-02) attaches token but does NOT refresh expired tokens before requests.

**Primary Fix: Update client.ts JWT interceptor to refresh tokens**

Modify `frontend/src/api/client.ts` request interceptor to refresh token BEFORE attaching it:

```typescript
// BEFORE (current implementation from 09-02-SUMMARY.md):
apiClient.interceptors.request.use(
  async (config) => {
    if (keycloak.authenticated) {
      const token = keycloak.token;
      if (token) {
        config.headers.Authorization = `Bearer ${token}`;
      }
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// AFTER (fixed implementation):
apiClient.interceptors.request.use(
  async (config) => {
    if (keycloak.authenticated) {
      try {
        // Refresh token if it expires within 30 seconds
        await keycloak.updateToken(30);
        
        const token = keycloak.token;
        if (token) {
          config.headers.Authorization = `Bearer ${token}`;
        }
      } catch (error) {
        console.error('[API Client] Token refresh failed:', error);
        // Token refresh failed - force re-login
        keycloak.login();
      }
    }
    return config;
  },
  (error) => Promise.reject(error)
);
```

**Why this fixes the issue:**
- Current code attaches whatever token exists (even if expired)
- Backend rejects expired tokens with 401 Unauthorized
- New code calls `keycloak.updateToken(30)` which:
  - Checks if token expires within 30 seconds
  - If yes: silently refreshes using refresh token
  - If no: does nothing (token still valid)
  - If refresh fails: redirects to login
- This fixes authentication for ALL API calls app-wide (not just locations)

**Secondary Fix: Add retry logic to useLocations hook**

Modify `frontend/src/hooks/useLocations.ts` to handle transient failures:

```typescript
import { useQuery } from '@tanstack/react-query';
import { locationsApi } from '../api/locations';

export function useLocations(params?: { include_deleted?: boolean }) {
  return useQuery({
    queryKey: ['locations', params],
    queryFn: async () => {
      const response = await locationsApi.getLocations(params);
      console.log('[useLocations] Fetched', response.data.length, 'locations');
      return response.data;
    },
    retry: 2, // Retry failed requests 2 times
    staleTime: 5 * 60 * 1000, // Cache for 5 minutes (same pattern as useSettings from 09-02)
  });
}
```

**Note:** Token refresh now happens in client.ts interceptor (once, globally) instead of per-hook. This is the correct pattern - centralized auth logic prevents duplication.
