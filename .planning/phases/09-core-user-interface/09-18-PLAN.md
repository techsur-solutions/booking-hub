  <action>
Create Flyway migration V3 to seed a test user with UUID matching the Keycloak test user's `sub` claim.

**Root cause analysis:**
- UAT Test #14 failed: "Error: Failed to load account information"
- `UserService.getOwnProfile()` calls `userRepository.findById(userId)` where `userId` comes from JWT `sub` claim
- Throws `UserNotFoundException` when no user record exists for the authenticated Keycloak user
- Phase 3 created the users table schema but NO seed data for test users
- Keycloak has test users (likely created manually or via Keycloak seed) but users_db has zero rows

**Migration content:**
```sql
-- V3: Seed test user for development/UAT
-- 
-- This user's UUID MUST match the 'sub' claim in Keycloak test user's JWT token.
-- To find the correct UUID:
-- 1. Log in to Keycloak admin console (http://localhost:9090)
-- 2. Navigate to Users -> View all users
-- 3. Click on your test user (e.g., testuser@example.com)
-- 4. Copy the user ID (UUID) from the URL or Details tab
-- 
-- For now, using a placeholder UUID that should be replaced with actual Keycloak user ID.
-- If Keycloak test user doesn't exist yet, create one with this exact UUID.

INSERT INTO users (id, email, first_name, last_name, deleted_at, created_at, updated_at)
VALUES 
    ('00000000-0000-0000-0000-000000000001'::uuid, 
     'testuser@example.com', 
     'Test', 
     'User', 
     NULL, 
     NOW(), 
     NOW())
ON CONFLICT (id) DO NOTHING;

-- Add a second test user for approval workflow testing
INSERT INTO users (id, email, first_name, last_name, deleted_at, created_at, updated_at)
VALUES 
    ('00000000-0000-0000-0000-000000000002'::uuid,
     'approver@example.com',
     'Booking',
     'Approver',
     NULL,
     NOW(),
     NOW())
ON CONFLICT (id) DO NOTHING;
```

**Idempotency:** `ON CONFLICT (id) DO NOTHING` ensures re-running seed doesn't fail.

**Next steps after migration:**
1. Restart users-permissions-service to apply migration: `docker compose restart users-permissions-service`
2. OR if Keycloak user UUID differs, update this migration file with correct UUIDs and re-run Flyway
3. Better long-term solution (Phase 10): implement Just-In-Time (JIT) user provisioning where first JWT auth auto-creates user record if missing

Update the error handling in MyAccount.tsx to provide actionable guidance when user record is missing.

**Current error message** (lines 122-132):
```typescript
<p style={{ marginBottom: 'var(--spacing-md)' }}>
  Failed to load account information. This may be due to:
</p>
<ul style={{ marginLeft: 'var(--spacing-lg)', marginBottom: 'var(--spacing-md)' }}>
  <li>Network connectivity issue</li>
  <li>Authentication token expired</li>
  <li>Server temporarily unavailable</li>
</ul>
```

**Enhanced error message:**
```typescript
<p style={{ marginBottom: 'var(--spacing-md)', fontWeight: 'bold' }}>
  Failed to load account information.
</p>
<p style={{ marginBottom: 'var(--spacing-md)' }}>
  {error instanceof Error && error.message.includes('404') ? (
    <>
      <strong>User record not found.</strong> Your Keycloak account exists, but no matching user record was found in the database.
    </>
  ) : (
    'This may be due to a network issue, expired authentication token, or the server being temporarily unavailable.'
  )}
</p>
{error instanceof Error && error.message.includes('404') && (
  <div style={{
    padding: 'var(--spacing-md)',
    backgroundColor: 'var(--color-info-light)',
    borderRadius: 'var(--radius-md)',
    marginBottom: 'var(--spacing-md)',
    fontSize: 'var(--font-size-sm)',
  }}>
    <p style={{ marginBottom: 'var(--spacing-sm)', fontWeight: 'bold' }}>
      For developers:
    </p>
    <ol style={{ marginLeft: 'var(--spacing-lg)', marginBottom: 0 }}>
      <li>Ensure your Keycloak user UUID matches the seed data in V3 migration</li>
      <li>Restart users-permissions-service to apply migrations: <code>docker compose restart users-permissions-service</code></li>
      <li>Or manually create your user record in users_db.users table</li>
    </ol>
  </div>
)}
<p style={{ fontSize: 'var(--font-size-sm)', color: 'var(--color-text-muted)' }}>
  Technical error: {error instanceof Error ? error.message : 'Unknown error'}
</p>
```

**Why this approach:**
- Detects 404 errors (UserNotFoundException returns 404 status)
- Provides specific guidance for the "missing user record" case
- Keeps generic guidance for other errors (network, auth, etc.)
- Developer-focused guidance in a distinct info box (not error red)
- Preserves the technical error message for debugging
