rememberMe.ts utility:
```typescript
export function saveRememberMe(email: string): void {
  document.cookie = `remember_me_email=${email}; max-age=${360 * 24 * 60 * 60}; path=/; SameSite=Strict`;
}

export function getRememberMeEmail(): string | null {
  const match = document.cookie.match(/remember_me_email=([^;]+)/);
  return match ? decodeURIComponent(match[1]) : null;
}

export function clearRememberMe(): void {
  document.cookie = 'remember_me_email=; max-age=0; path=/';
}
```

On Login page mount: if Remember Me email exists, pre-fill email display (not editable, just informational "Logging in as {email}").

Post-login redirect: read ?redirect= query param from URL, default to /calendar if absent.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted email in password reset request, untrusted token in password reset complete |
| client→cookie | Remember Me email stored client-side, could be manipulated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-15-01 | Information disclosure | Password reset request | mitigate | Identical success message for valid/invalid emails (no enumeration attack); backend (Phase 3) already implements this per FRD-BookingHub.md §6.3 |
| T-09-15-02 | Tampering | Password reset token | mitigate | Token validated server-side (Phase 3 implementation); expiry checked, one-time-use enforced; client-side token is read-only from URL param, not editable |
| T-09-15-03 | Spoofing | Remember Me cookie | accept | Cookie stores email only (not credentials); used for UI pre-fill, not authentication; SameSite=Strict prevents CSRF; acceptable risk (user convenience vs. minor email disclosure on shared device) |
| T-09-15-04 | Elevation of privilege | My Account name editing | mitigate | Backend (Phase 3) enforces user can only edit their own name (not other users); admin restrictions on role/email changes enforced server-side; client UI respects read-only fields |
</threat_model>
