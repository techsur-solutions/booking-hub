<objective>
Implement the Users Admin screen with table view, separate Create and Edit forms enforcing admin vs self restrictions (admins can edit all fields for other users, but users editing themselves can only change name/email, not password/roles) — so user account management follows principle of least privilege.

Purpose: User accounts gate access to the entire system; admins need full CRUD capability while preventing privilege escalation via self-editing.
Output: Fully functional Users Admin with table, Create form (admin-only), Edit form (admin vs self field restrictions), and Playwright tests.
</objective>

export const usersApi = {
  getAll: () => apiClient.get<User[]>('/users'),
  getById: (id: string) => apiClient.get<User>(`/users/${id}`),
  create: (data: UserCreateRequest) => apiClient.post<User>('/users', data),
  update: (id: string, data: UserUpdateRequest) => apiClient.put<User>(`/users/${id}`, data),
  updateSelf: (data: UserSelfUpdateRequest) => apiClient.put<User>('/users/me', data) // Phase 3 Plan 04 type-level guard
};

  <files>frontend/src/components/admin/UserEditForm.tsx, frontend/src/pages/admin/UserEdit.tsx</files>
  <action>
Create user edit form with conditional field rendering per UI-ADMIN-04 admin vs self restrictions.

**UserEditForm.tsx** — Edit form with conditional fields based on whether editing self or another user:

Determine edit mode:
```typescript
const currentUserId = keycloak.tokenParsed?.sub; // Current user's Keycloak UUID
const isSelfEdit = currentUserId === userId; // userId from route param
```

**If editing SELF (isSelfEdit === true):**
- Show fields: `display_name`, `email` (read-only with note "Contact admin to change email")
- Hide fields: `password`, `roles`
- Submit calls `usersApi.updateSelf({ display_name })` (Phase 3 Plan 04 type-level guard — UserSelfUpdateRequest has NO password/roles fields)
- Show note: "To change password, use My Account → Change Password"

**If editing OTHER user (admin editing another, isSelfEdit === false):**
- Show all fields: `display_name`, `email`, `roles` (multi-select, same 17 roles as Create form)
- NO password field (password changes via separate "Reset Password" action or My Account flow)
- Submit calls `usersApi.update(userId, { display_name, email, roles })`

On successful save: show StateConfirmationBanner ("User updated"), navigate back to `/admin/users`.

**UserEdit.tsx** — Route page for `/admin/users/:id/edit`:
- Fetches user by id via `usersApi.getById(id)`
- Renders UserEditForm pre-filled with existing values
- Passes `userId` from route param to form for isSelfEdit determination
