<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
Wave 1 Plans (10-01 through 10-07) implemented all admin CRUD screens. Phase 9 Plan 01 implemented responsive navigation transforming sidebar to bottom nav bar at mobile breakpoint.
  </what-built>
  <how-to-verify>
**Manual testing at mobile resolutions:**

1. **Open browser at 375px viewport (iPhone SE):**
   - Chrome DevTools → Responsive mode → iPhone SE (375 x 667)
   - Navigate to `http://localhost:3000`

2. **Verify bottom nav bar replaces sidebar:**
   - Assert: Sidebar is NOT visible (no hamburger menu in header)
   - Assert: Bottom nav bar appears at bottom of viewport (sticky/fixed position)
   - Assert: Bottom nav shows 4-5 primary items (Calendar, Approvals if role present, Feeds, Admin if role present, Account)
   - Assert: Icons + labels (or icons only with tooltips) visible in bottom nav
   - Assert: Tapping nav item navigates to correct route

3. **Verify calendar defaults to Day View:**
   - Upon login, default landing page should be `/bookings?view=day` (NOT `/bookings?view=month`)
   - Assert: Day View shows hourly slots (NOT month grid which is unreadable at 375px)
   - Assert: Calendar events readable (titles not excessively truncated)
   - Assert: View switcher tabs (Month/Day/List) visible and tappable

4. **Verify List View as primary booking discovery:**
   - Navigate to List View (`/bookings?view=list`)
   - Assert: Table/list layout readable (rows stack vertically if needed)
   - Assert: Each booking shows: title, location, time, status, conflict badge if present
   - Assert: Tap row opens Booking Detail Modal

5. **Verify forms stack with full-width inputs:**
   - Navigate to Locations Create form (`/admin/locations/new`)
   - Assert: All form fields stack vertically (one field per row)
   - Assert: Input fields are full-width (edge-to-edge minus padding)
   - Assert: Input fields have min-height ~44px (thumb-friendly tap targets per iOS Human Interface Guidelines)
   - Assert: On-screen keyboard does not obscure active input field (form scrolls or viewport adjusts)

6. **Verify admin tables readable on mobile:**
   - Navigate to Locations Admin (`/admin/locations`)
   - Assert: Table rows stack or scroll horizontally (all columns accessible via horizontal swipe)
   - OR table transforms to card layout (one card per location, showing key fields)

7. **Repeat verification at 414px viewport (iPhone Pro Max):**
   - Change DevTools viewport to 414 x 896
   - Re-verify bottom nav, Day View default, forms full-width

**Success signal:** Bottom nav bar present, calendar defaults to Day View, List View readable, forms full-width with thumb-friendly tap targets.
  </how-to-verify>
  <resume-signal>Type "approved" to continue, or describe any layout issues found (e.g., "sidebar still visible at 375px", "form inputs too narrow to tap", "bottom nav obscures content")</resume-signal>
</task>
