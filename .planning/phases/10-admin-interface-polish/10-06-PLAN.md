**Section 1: Approval Workflow**

  - Label: "Auto-approve bookings"
  - Help text: "When ON, new bookings are automatically approved. When OFF, bookings require manual approval."
  - Propagation indicator: After save, show inline badge "Changes take effect immediately for new bookings" (addressing JRN-03.2 "did the approval setting actually propagate?" concern)

**Section 2: Calendar Display**
- `slot_size` (number input, minutes, e.g., 15, 30, 60):
  - Label: "Time slot size (minutes)"
  - Default: 30
- `min_time` (time input, HH:mm format, e.g., "08:00"):
  - Label: "Calendar start time"
  - Default: "08:00"
- `max_time` (time input, HH:mm format, e.g., "18:00"):
  - Label: "Calendar end time"
  - Default: "18:00"

**Section 3: Display & Feeds**
- "Preview Display Board" button: Opens `/display-board` in new tab (convenience shortcut)
- "Copy feed links" button: Opens modal/popover showing RSS2/iCal/JSON feed URLs with copy-to-clipboard buttons (re-uses logic from Feed Subscription page if already built in Phase 9 Plan 14)

**Form behavior:**
- Fetch current settings via `settingsApi.getCurrent()` calling v1.0 backend `GET /settings/current` (singleton entity from Phase 4 Plan 05)
- On submit: call `settingsApi.update({ approveBooking, slot_size, min_time, max_time })` calling `PUT /settings/1` (Phase 4 singleton pattern)
- On successful save: show StateConfirmationBanner with timestamp ("Settings updated at [HH:mm:ss]"), persist form state (no navigation, user stays on settings page)

**settingsApi.ts** — API client methods:
```typescript
export const settingsApi = {
  getCurrent: () => apiClient.get<Settings>('/settings/current'),
  update: (data: SettingsUpdateRequest) => apiClient.put<Settings>('/settings/1', data) // Singleton entity, id always 1
};
```
