  <action>
Conduct WCAG AA accessibility audit and remediate issues across all UI components.

**ARIA labels (WCAG 4.1.2):**
- Add `aria-label` or `aria-labelledby` to all interactive elements lacking visible text labels:
  - Icon-only buttons (Edit, Delete, Close icons)
  - Form inputs (ensure `<label>` with `htmlFor` or `aria-label`)
  - Navigation items (sidebar links, bottom nav icons)
- Example: `<button aria-label="Delete location">{deleteIcon}</button>`

**Keyboard navigation (WCAG 2.1.1):**
- Verify tab order is logical (top-to-bottom, left-to-right)
- Ensure all interactive elements focusable via keyboard (no `tabindex="-1"` on critical actions)
- Add keyboard event handlers for custom components (e.g., modal close on Escape key)
- Test: Navigate entire app using only Tab, Enter, Escape, Arrow keys

**Focus indicators (WCAG 2.4.7):**
- Add visible focus ring to all interactive elements:
  ```css
  /* frontend/src/styles/a11y.css */
  :focus-visible {
    outline: 2px solid #0066CC; /* Blue outline */
    outline-offset: 2px;
  }
  button:focus-visible, a:focus-visible, input:focus-visible {
    outline: 2px solid #0066CC;
  }
  ```
- DO NOT use `outline: none` without replacement focus indicator

**Color contrast (WCAG 1.4.3):**
- Audit all text colors against backgrounds using contrast checker tool (e.g., WebAIM Contrast Checker)
- Required ratios: 4.5:1 for normal text (<18pt), 3:1 for large text (≥18pt or ≥14pt bold)
- Fix low-contrast issues:
  - Faded text (e.g., placeholder text, secondary labels) → darken to meet 4.5:1
  - Light badges/chips → add border or increase background darkness
- Document contrast ratios in audit-checklist.md

**Screen reader compatibility (WCAG 1.3.1, 4.1.2):**
- Add semantic HTML: `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`
- Add landmark roles if semantic HTML insufficient: `role="navigation"`, `role="main"`
- Add `aria-live` regions for dynamic content (toast notifications, inline errors)
- Add screen-reader-only text for context:
  ```css
  .sr-only {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
    white-space: nowrap;
    border: 0;
  }
  ```

**accessibility.spec.ts structure:**
```typescript
import { test, expect } from '@playwright/test';
import { injectAxe, checkA11y } from '@axe-core/playwright';

test.describe('Accessibility audit', () => {
  test('Calendar View meets WCAG AA', async ({ page }) => {
    await page.goto('/bookings?view=month');
    await injectAxe(page);
    await checkA11y(page, null, {
      detailedReport: true,
      detailedReportOptions: { html: true }
    });
  });

  test('Locations Admin meets WCAG AA', async ({ page }) => {
    await page.goto('/admin/locations');
    await injectAxe(page);
    await checkA11y(page);
  });

  test('Booking Create Form meets WCAG AA', async ({ page }) => {
    await page.goto('/bookings/new');
    await injectAxe(page);
    await checkA11y(page);
  });

  test('Keyboard navigation: Tab through Calendar View', async ({ page }) => {
    await page.goto('/bookings?view=month');
    await page.keyboard.press('Tab');
    // Assert first focusable element has focus
    const firstFocused = await page.evaluate(() => document.activeElement?.tagName);
    expect(['A', 'BUTTON', 'INPUT']).toContain(firstFocused);
    
    // Tab through 10 elements, verify focus moves
    for (let i = 0; i < 10; i++) {
      await page.keyboard.press('Tab');
    }
    // Assert focus moved (activeElement changed)
  });

  test('Screen reader: Form inputs have labels', async ({ page }) => {
    await page.goto('/admin/locations/new');
    const inputsWithoutLabels = await page.locator('input:not([aria-label]):not([id])').count();
    expect(inputsWithoutLabels).toBe(0); // All inputs must have aria-label or associated label
  });
});
```
