```yaml
name: Regression Suite

on:
  push:
    branches: [ main, 'feature/**' ]
  pull_request:
    branches: [ main ]

env:
  JAVA_VERSION: '21'
  NODE_VERSION: '20'

jobs:
  backend-tests:
    name: Backend Integration Tests
    runs-on: ubuntu-latest
    
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_DB: test_db
          POSTGRES_USER: test_user
          POSTGRES_PASSWORD: test_pass
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
        ports:
          - 5432:5432
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
      
      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
          cache: 'maven'
      
      - name: Run backend tests
        working-directory: ./services
        env:
          SPRING_PROFILES_ACTIVE: test
          DB_HOST: localhost
          DB_PORT: 5432
          DB_NAME: test_db
          DB_USER: test_user
          DB_PASSWORD: test_pass
        run: |
          # Run tests for all services (fail fast on first failure)
          for service_dir in */; do
            service_name=$(basename "$service_dir")
            echo "Testing $service_name..."
            (cd "$service_dir" && mvn clean test -B)
          done
      
      - name: Publish test report
        uses: dorny/test-reporter@v1
        if: always()
        with:
          name: Backend Test Results
          path: 'services/*/target/surefire-reports/*.xml'
          reporter: java-junit
          fail-on-error: true

  frontend-tests:
    name: Frontend E2E Tests
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
      
      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json
      
      - name: Install dependencies
        working-directory: ./frontend
        run: npm ci
      
      - name: Install Playwright browsers
        working-directory: ./frontend
        run: npx playwright install --with-deps chromium
      
      - name: Run E2E tests
        working-directory: ./frontend
        env:
          VITE_E2E_MODE: 'true'
        run: npx playwright test --workers=1 --reporter=list
      
      - name: Upload Playwright report
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: playwright-report
          path: frontend/playwright-report/
          retention-days: 7

  regression-summary:
    name: Regression Suite Summary
    runs-on: ubuntu-latest
    needs: [backend-tests, frontend-tests]
    if: always()
    
    steps:
      - name: Check test results
        run: |
          if [ "${{ needs.backend-tests.result }}" != "success" ] || [ "${{ needs.frontend-tests.result }}" != "success" ]; then
            echo "❌ Regression suite FAILED"
            echo "Backend: ${{ needs.backend-tests.result }}"
            echo "Frontend: ${{ needs.frontend-tests.result }}"
            exit 1
          else
            echo "✅ Regression suite PASSED"
          fi
```

Key features:
- **Postgres service** for backend tests (matches docker-compose test setup from Phase 3)
- **Parallel jobs** (backend + frontend run independently)
- **Test reports** uploaded as artifacts (JUnit XML for backend, Playwright HTML for frontend)
- **Fail-fast** on first test failure (per F13.4 blocking requirement)
- **Summary job** consolidates results for branch protection rule

  <action>
Create local script developers can run before pushing to verify all tests pass.

**File:** `scripts/ci/run-full-regression.sh`

```bash
#!/bin/bash
set -euo pipefail

echo "========================================"
echo "BookingHub Regression Suite (Local Run)"
echo "========================================"
echo ""

# Check docker-compose is running
if ! docker compose ps | grep -q 'Up'; then
  echo "⚠️  docker-compose stack not running. Starting services..."
  docker compose up -d
  echo "Waiting for services to be healthy..."
  sleep 10
fi

FAILED=0

# Backend tests
echo "========================================" 
echo "Running Backend Integration Tests"
echo "========================================"
echo ""

cd services
for service_dir in */; do
  service_name=$(basename "$service_dir")
  
  # Skip if no pom.xml (e.g., api-gateway might have different build)
  if [ ! -f "$service_dir/pom.xml" ]; then
    echo "⏭️  Skipping $service_name (no pom.xml)"
    continue
  fi
  
  echo "Testing $service_name..."
  if (cd "$service_dir" && mvn test -q); then
    echo "✅ $service_name passed"
  else
    echo "❌ $service_name FAILED"
    FAILED=$((FAILED + 1))
  fi
  echo ""
done
cd ..

# Frontend tests
echo "========================================"
echo "Running Frontend E2E Tests"
echo "========================================"
echo ""

cd frontend
if npm run test:e2e 2>&1 | grep -E 'passed|failed'; then
  if npm run test:e2e 2>&1 | grep -q 'failed'; then
    echo "❌ Frontend tests FAILED"
    FAILED=$((FAILED + 1))
  else
    echo "✅ Frontend tests passed"
  fi
else
  echo "❌ Frontend tests FAILED (could not parse output)"
  FAILED=$((FAILED + 1))
fi
cd ..

# Summary
echo ""
echo "========================================"
if [ $FAILED -eq 0 ]; then
  echo "✅ All regression tests PASSED"
  echo "Safe to push."
  exit 0
else
  echo "❌ $FAILED test suite(s) FAILED"
  echo "Fix failures before pushing."
  exit 1
fi
```

Make executable: `chmod +x scripts/ci/run-full-regression.sh`

Add npm script to `frontend/package.json` (if not exists):
```json
{
  "scripts": {
    "test:e2e": "playwright test --workers=1 --reporter=list"
  }
}
```

# Branch Protection Setup

**Purpose:** Enforce F13.4 requirement that regression suite must pass before any release.

## GitHub Branch Protection Rules

Navigate to repository **Settings → Branches → Branch protection rules → Add rule**

### Rule for `main` branch:

**Branch name pattern:** `main`

**Protect matching branches:**
- ✅ **Require a pull request before merging**
  - Require approvals: 1 (recommended for production)
  - Dismiss stale pull request approvals when new commits are pushed: ✅
  
- ✅ **Require status checks to pass before merging**
  - Require branches to be up to date before merging: ✅
  - **Status checks that are required:**
    - `Regression Suite Summary` (the `regression-summary` job from workflow)
    - `Backend Integration Tests` (optional — summary covers it)
    - `Frontend E2E Tests` (optional — summary covers it)
  
  **Note:** Status check names appear in the list AFTER the workflow runs at least once. Push a commit to trigger the workflow, then return here to select the checks.

- ✅ **Require conversation resolution before merging**
  - All PR review comments must be resolved before merge

- ✅ **Do not allow bypassing the above settings**
  - Admins cannot bypass (ensures even urgent fixes are tested)

**Result:** Any PR that fails the regression suite is blocked from merging until fixed.

## Local Pre-Push Verification

Developers should run the local regression suite before pushing:

```bash
bash scripts/ci/run-full-regression.sh
```

This runs the SAME tests CI will run, catching failures early.

**Pre-commit hook (optional):**

Add to `.git/hooks/pre-push`:

```bash
#!/bin/bash
echo "Running regression suite before push..."
if ! bash scripts/ci/run-full-regression.sh; then
  echo ""
  echo "❌ Push aborted: regression suite failed"
  echo "Fix test failures before pushing."
  exit 1
fi
```

Make executable: `chmod +x .git/hooks/pre-push`

**Note:** This is optional — CI is the enforcement point, not local hooks.

## Monitoring Test Failures

**When CI fails:**

1. Check **Actions** tab for workflow run details
2. Click failed job (Backend/Frontend) to see logs
3. Download test report artifacts (JUnit XML / Playwright HTML)
4. Fix failing tests locally
5. Re-push — CI re-runs automatically

**When a previously passing test now fails (regression detected):**

1. This is the EXACT scenario F13.4 exists to catch
2. DO NOT merge the PR
3. Either:
   - Fix the code to restore passing behavior (if unintended regression)
   - Update the test if behavior intentionally changed (rare — requires product owner approval)

## Updating Traceability Matrix on Test Changes

When a test is added/modified:

1. Update `.planning/traceability-matrix.csv` with test_ref and status
2. Re-run coverage analysis:
   ```bash
   bash scripts/traceability/analyze-coverage.sh
   ```
3. Commit matrix + coverage report updates in same PR as test changes

## CI Workflow Maintenance

**Updating the workflow:**

File: `.github/workflows/regression-suite.yml`

Common changes:
- Add new test suites (e.g., integration tests for Phase 6 RabbitMQ consumers)
- Adjust timeouts (if tests grow slower)
- Add caching (Maven local repo, npm cache — already configured)

**Do NOT:**
- Remove `fail-on-error: true` (defeats F13.4 enforcement)
- Add `continue-on-error: true` to test jobs
- Skip tests in CI while enabling locally

## Troubleshooting

**"Status check not found" when setting up branch protection:**
- Workflow must run successfully at least once before status check appears
- Push a commit to main, wait for workflow, then configure protection

**Tests pass locally but fail in CI:**
- Check CI Postgres version matches docker-compose (postgres:16)
- Check environment variables (SPRING_PROFILES_ACTIVE=test, VITE_E2E_MODE=true)
- Download test artifacts from failed run for detailed logs

**CI is slow:**
- Backend tests: Maven dependency caching configured (uses `actions/setup-java` cache)
- Frontend tests: npm cache configured, Playwright browsers cached
- Typical run time: 5-10 minutes for full suite

---
*Branch protection is the enforcement mechanism for "no functionality lost" — do not disable it.*

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer→CI-config | Developer could modify .github/workflows to disable test enforcement |
| CI→merge-gate | GitHub branch protection enforces CI passing (admin-configurable) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-05 | Tampering | Developer disables fail-on-error in workflow | mitigate | Branch protection rule "Do not allow bypassing" prevents merge without CI pass. Code review of workflow changes (grep for `continue-on-error: true` or removal of `fail-on-error`) catches tampering attempts before merge. |
| T-08-06 | Elevation of Privilege | Admin bypasses branch protection to merge failing PR | accept | GitHub's "Do not allow bypassing" setting blocks even admins, but can be toggled by repo owner. This is a GitHub platform trust assumption (repo owner is authorized to make this call). Document as requirement in branch-protection-setup.md. |
| T-08-07 | Denial of Service | Malicious test causes CI to hang indefinitely | mitigate | GitHub Actions has default job timeout (360 minutes), configurable per job. Add explicit `timeout-minutes: 30` to backend-tests and frontend-tests jobs to fail fast on hangs. |
</threat_model>
