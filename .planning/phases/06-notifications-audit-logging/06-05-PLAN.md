<objective>
Enable RabbitMQ consumer registration by adding the missing @EnableRabbit annotation to both notifications-service and audit-log-service main application classes, closing the UAT-proven gap that prevented all 8 blocker tests from passing.

Purpose: Plans 06-02 and 06-04 correctly implemented @RabbitListener methods for all notification and audit event types, but Spring Boot does not process @RabbitListener annotations unless @EnableRabbit is present on a @Configuration or @SpringBootApplication class. UAT automated testing confirmed consumer count = 0 for both services, and the root cause was definitively identified as the missing @EnableRabbit annotation. This simple configuration fix activates all the consumer infrastructure already built by Wave 1 and Wave 2 plans.

Output: Both services boot with active RabbitMQ consumers, UAT tests 1-5 and 9 pass, and the notification/audit event pipeline is fully functional.
</objective>

Current state (from UAT gap analysis):
```java
@SpringBootApplication
public class NotificationsServiceApplication {

        SpringApplication.run(NotificationsServiceApplication.class, args);
```

Required change:
1. Add import: `import org.springframework.amqp.rabbit.annotation.EnableRabbit;`
2. Add @EnableRabbit annotation above @SpringBootApplication

Result should be:
```java
package com.bookinghub.notifications;

import org.springframework.amqp.rabbit.annotation.EnableRabbit;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@EnableRabbit
@SpringBootApplication
public class NotificationsServiceApplication {
    public static void main(String[] args) {
        SpringApplication.run(NotificationsServiceApplication.class, args);
    }
}
```

Why @EnableRabbit is required: Spring Boot's @SpringBootApplication does NOT automatically enable @RabbitListener processing. The @EnableRabbit annotation is required to trigger Spring AMQP's annotation-driven listener endpoint detection. Without it, NotificationConsumerService's two @RabbitListener methods (created by plan 06-02) are never registered as message consumers, even though the methods exist and the RabbitConfig container factory is correctly configured.

Gap traceability: Fixes UAT tests 1, 2, 3, 4, 5 (all notification consumer tests). UAT automation confirmed consumer_count = 0 before this fix.
