Create `V1__init_schema.sql` with the EXACT DDL from TechArch-BookingHub.md §3.3 "audit-log-service — database `audit_db`" verbatim, **including the `REVOKE UPDATE, DELETE` statement which is the load-bearing immutability control** — this table has no `updated_at` column (immutable rows don't need one) so no trigger is attached:

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE audit_log_entries (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    actor_id        UUID NOT NULL,
    occurred_at     TIMESTAMPTZ NOT NULL,
    entity_type     VARCHAR(64) NOT NULL,              -- 'booking' | 'location' | 'resource' | 'user' | 'role' | 'settings' | 'permission' | ...
    entity_id       UUID NOT NULL,
    action_type     VARCHAR(64) NOT NULL,              -- 'created' | 'updated' | 'deleted' | 'approved' | 'denied' | ...
    before_values   JSONB NULL,
    after_values    JSONB NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_entity ON audit_log_entries (entity_type, entity_id);
CREATE INDEX idx_audit_actor ON audit_log_entries (actor_id);
CREATE INDEX idx_audit_occurred_at ON audit_log_entries (occurred_at);
-- Immutability enforced at the Postgres role level: the application's runtime role
-- is granted INSERT, SELECT only on audit_log_entries — no UPDATE/DELETE grant exists.
REVOKE UPDATE, DELETE ON audit_log_entries FROM PUBLIC;
```

No entity/repository/controller classes, no `@RabbitListener` — Phase 6 scope. The application's runtime Postgres role (`audit_svc`, created by the integration plan's init script) must only ever be `GRANT`ed `SELECT, INSERT` on this table — never `UPDATE`/`DELETE` — so immutability holds even if a future Phase-6 bug attempts an update; this plan's migration enforces the `REVOKE FROM PUBLIC` baseline, and the role-level grant restriction is the integration plan's (02-12) responsibility when it provisions `audit_svc`.
