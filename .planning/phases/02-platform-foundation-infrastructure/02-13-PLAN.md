<objective>
Fix the API Gateway startup failure caused by eager JWT decoder initialization attempting to resolve the Keycloak hostname before the service is available. Implement lazy JWT decoder initialization so the Gateway can start independently, and add proper health check dependencies in docker-compose.yml.

Purpose: UAT test 5 found that the Gateway container crash-loops with `java.net.UnknownHostException: keycloak` during bean creation. This blocks the entire platform from starting. The fix allows the Gateway to start even when Keycloak is temporarily unavailable, maintaining the fail-closed posture at request time while allowing successful boot.

Output: A working full-stack docker-compose environment where all services start successfully, Gateway can route requests, and JWT validation works correctly once Keycloak is healthy.
</objective>

<task type="auto">
  <name>Implement lazy JWT decoder initialization in SecurityConfig</name>
  <files>services/api-gateway/src/main/java/com/bookinghub/gateway/config/SecurityConfig.java</files>
  <action>
Replace the eager `ReactiveJwtDecoders.fromIssuerLocation(issuerUri)` call in `failClosedJwtDecoder()` with lazy initialization using `NimbusReactiveJwtDecoder.withJwkSetUri()`. The current implementation fetches JWKS at bean creation time (line 92), causing startup failure when Keycloak is unreachable. Lazy initialization defers the fetch until the first JWT validation request arrives.

Specific changes to SecurityConfig.java:

1. Add import: `import org.springframework.security.oauth2.jwt.NimbusReactiveJwtDecoder;`

2. Replace the `failClosedJwtDecoder()` method (lines 90-101) with lazy initialization:

```java
/**
 * Fail-closed JWT decoder with LAZY initialization: defers JWKS fetch until first validation request.
 * This allows the Gateway to start even when Keycloak is temporarily unavailable.
 * At request time: if Keycloak's JWKS endpoint is unreachable, returns 503 SERVICE_UNAVAILABLE
 * rather than treating unverifiable tokens as valid (fail-closed posture).
 */
@Bean
public ReactiveJwtDecoder failClosedJwtDecoder() {
    // Lazy initialization: construct JWK Set URI but do NOT fetch yet
    String jwkSetUri = issuerUri + "/protocol/openid-connect/certs";
    
    NimbusReactiveJwtDecoder decoder = NimbusReactiveJwtDecoder.withJwkSetUri(jwkSetUri).build();
    
    // Wrap with fail-closed error handling: JWKS fetch failures → 503
    return token -> decoder.decode(token)
            .onErrorResume(ex -> {
                // Any failure reaching JWKS endpoint → fail closed with 503
                // This includes network errors, timeouts, DNS failures, etc.
                return Mono.error(new JwksUnreachableException(
                        "Identity provider JWKS endpoint unreachable - failing closed", ex));
            });
}
```

Why withJwkSetUri() instead of fromIssuerLocation(): `fromIssuerLocation()` immediately fetches the OIDC discovery document and JWKS during bean creation. `withJwkSetUri()` constructs the decoder but defers all network calls until the first `decode()` invocation. This aligns with TechArch fail-closed-but-not-fail-crashed posture (the service starts, but requests fail until Keycloak is reachable).

The fail-closed error handling is preserved: if JWKS is unreachable at request time, the custom `JwksUnreachableException` causes a 503 response, never allowing unverified tokens through.
