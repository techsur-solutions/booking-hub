  <files>frontend/src/auth/AuthProvider.tsx, frontend/src/auth/ProtectedRoute.tsx, frontend/src/auth/keycloak.ts, frontend/Dockerfile, frontend/.dockerignore, frontend/nginx.conf, frontend/e2e/auth-redirect.spec.ts</files>
  <action>
Add `keycloak-js` as a dependency. `frontend/src/auth/keycloak.ts`:
```typescript
import Keycloak from "keycloak-js";

export const keycloak = new Keycloak({
  url: import.meta.env.VITE_KEYCLOAK_URL ?? "http://localhost:8180",
  realm: "bookinghub",
  clientId: "bookinghub-frontend",
});
```
No client secret anywhere (this is a public PKCE client, matching the realm config from plan 02-09).

`AuthProvider.tsx` — a React context provider that calls `keycloak.init({ onLoad: 'check-sso', pkceMethod: 'S256', silentCheckSsoRedirectUri: window.location.origin + '/silent-check-sso.html' })` once on mount, exposes `{ authenticated, keycloak }` via context, and renders a loading state until `init()` resolves (never renders children with an indeterminate auth state). Skip real Keycloak initialization entirely when `import.meta.env.VITE_E2E_MODE === 'true'`, instead providing a stub `{ authenticated: true, keycloak: <stub> }` synchronously — this is the Task 1 convention the navigation test relies on.

`ProtectedRoute.tsx` — wraps a route element; if `authenticated` is false (and not in E2E mode), calls `keycloak.login()` (triggers the full Authorization Code + PKCE redirect to Keycloak) and renders nothing (not even a flash of the protected child) while the redirect is in flight. Apply `ProtectedRoute` to every route EXCEPT `/feeds` and `/display-board` (public per F9.6) in `src/App.tsx`/`src/routes/index.tsx`.

`frontend/Dockerfile` — multi-stage: `node:20-alpine` builder (`npm ci && npm run build`) → `nginx:alpine` runtime, `COPY --from=builder /app/dist /usr/share/nginx/html`, `COPY nginx.conf /etc/nginx/conf.d/default.conf`, `EXPOSE 80`. `nginx.conf` — serves the SPA with a catch-all `try_files $uri /index.html;` fallback (client-side routing support).

`frontend/e2e/auth-redirect.spec.ts` (Playwright, run WITHOUT `VITE_E2E_MODE` so the real `ProtectedRoute` gate is active):
1. Use `page.route('**/realms/bookinghub/protocol/openid-connect/auth**', route => route.abort())` (or `fulfill` with a dummy 200 page) to intercept the Keycloak redirect BEFORE it actually navigates away — no live Keycloak server is required for this assertion.
2. Navigate to `/calendar` (protected) and assert the intercepted request's URL matches the Keycloak authorize-endpoint pattern (`/realms/bookinghub/protocol/openid-connect/auth`) and includes `code_challenge_method=S256` (proving PKCE, not implicit/plain flow) — proving the redirect fires correctly, never rendering the Calendar placeholder's content first.
3. Navigate to `/feeds` (public) and assert NO redirect request to the Keycloak authorize endpoint occurs, and the Feeds Landing placeholder renders directly.
4. Navigate to `/display-board` (public) and assert the same — no redirect, content renders directly, and assert no nav chrome is present (full-screen kiosk layout).
